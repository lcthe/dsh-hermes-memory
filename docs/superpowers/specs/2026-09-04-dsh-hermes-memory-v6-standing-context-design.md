# dsh-hermes-memory V6 设计规范：用户画像与常驻指令

**日期：** 2026-09-04
**状态：** 待实现

## 1. 目标

V6 增加一组独立于普通记忆的常驻上下文，用于保存用户画像、助手角色和需要跨会话持续生效的指令。常驻上下文在插件启用时随每个新 agent 生命周期注入一次，不受普通记忆 `automaticInjection` 开关影响。

普通记忆仍是可检索的参考信息；常驻上下文是明确要求模型持续遵守的用户控制信息。后台捕获、后台复盘和后续 consolidation 都不得把普通记忆自动升级为常驻上下文。

## 2. 数据模型

新增 `standing` 表，每条记录包含：

- 稳定 ID；
- `kind: 'profile' | 'instruction'`；
- 非空 `content`；
- `createdAt`、`updatedAt`；
- 创建来源的 session ID 和 event sequence（存在时）；
- `schemaVersion: 1`。

常驻上下文只属于当前 DSH 用户，不设置 project scope。项目规则继续使用现有 project memory，避免把仓库约定错误提升为所有会话都生效的指令。

硬限制为最多 20 条、渲染后总计最多 2,000 字符、单条最多 500 字符。达到限制时拒绝新增，不隐式删除旧条目。

## 3. 用户操作

新增三个模型可见工具：

- `memory_pin`：仅在用户明确要求长期记住、固定角色或持续遵守时新增常驻条目；
- `memory_pins`：列出有界的常驻条目；
- `memory_unpin`：按稳定 ID 删除常驻条目。

`memory_pin` 的工具说明必须明确禁止模型自行提升普通记忆。Host 仍执行参数校验、内容安全扫描、精确重复检查、数量和字符预算校验。后台自动捕获和自动复盘没有调用这些写操作的接口。

## 4. 会话注入

V6 在 `agent/session-start` 读取常驻表，按 `kind`、更新时间和 ID 稳定排序，并通过 `agent.inject()` 写入一条有来源标记的用户角色消息。注入内容包含清晰边界：它只承载已保存的用户画像和常驻指令，不能覆盖更高优先级的系统指令或当前用户消息。

每个 agent 生命周期最多注入一次。恢复已有 session 时，通过已记录的插件消息识别是否已经注入；进程内 `WeakSet` 只用于减少重复检查，不能作为唯一幂等依据。成功注入是模型可见输入，因此必须留在 session log 中。

读取、渲染或注入失败全部 fail-soft，只记录稳定错误码，不记录原始常驻内容。

## 5. 设置和界面

新增设置：

- `standingContextEnabled`，默认 `true`；
- `standingMaxEntries`，默认和上限均为 `20`；
- `standingMaxChars`，默认和上限均为 `2_000`。

数量和字符硬上限属于安全约束，不提供超过上限的配置。设置页增加“常驻上下文”卡片，只展示开关和预算状态；条目的新增、查看和删除先通过工具完成，不在 V6 建设独立管理页。

## 6. 测试和验收

- 常驻记录可以跨插件重启读取；
- 普通自动注入关闭时，常驻上下文仍注入；
- 同一 agent 生命周期和恢复 session 不重复注入；
- 超过单条、总字符或条数上限时拒绝写入且不改变已有数据；
- secret、提示注入、不可见字符和外泄指令仍被拒绝；
- 后台捕获和后台复盘不能创建常驻条目；
- `memory_unpin` 找不到 ID 时不删除其他条目；
- 设置、工具、存储、注入和插件 teardown 均有聚焦测试；
- typecheck、测试、build 和打包检查通过。

## 7. 非目标

- 不从普通记忆自动推断或提升常驻指令；
- 不把项目规则注入所有工作区；
- 不把常驻内容复制到 Markdown 或第二套数据库；
- 不增加每一步重复注入。
